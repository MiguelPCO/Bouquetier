# Enlace compartido: encoding compacto y generación de OG image fuera del file-convention de Next

**Encoding.** El Ramo se codifica en la URL como `especie:cantidad` por especie (orden por primera aparición), no como lista completa tallo-por-tallo. Se consideró la lista completa por fidelidad pixel-exacta, pero se descartó: el desempate por `uid` dentro de un mismo rol solo reordena 1-2 tallos entre sí de forma imperceptible a simple vista, y el ahorro de URL es real (hasta 24 tallos posibles). Si en el futuro se necesita fidelidad exacta (ej. animaciones que dependan del orden de inserción real), este encoding hay que revisarlo — los enlaces ya compartidos con el formato viejo dejarían de reconstruir igual.

**OG image.** La imagen de Open Graph se genera en un Route Handler propio (`app/api/og/route.ts`) que rasteriza con `sharp`, no con el file-convention `opengraph-image.tsx` de Next.js. Decisión forzada, no de preferencia: ese file-convention solo recibe `params` de rutas dinámicas, nunca `searchParams` — no hay forma de generar una imagen que dependa de `?s=...` con esa convención. Queda anotado para que nadie intente "simplificar" moviéndolo al file-convention más adelante.
